### Задание 1

Опишите основные преимущества использования масштабирования методами:

- активный master-сервер и пассивный репликационный slave-сервер; 
- master-сервер и несколько slave-серверов;


*Дайте ответ в свободной форме.*

### Решение 1

Масштабирование Master-Slave позволяет распределить нагрузку, повысить отказоустойчивость и обеспечить сохранность данных.
Активный Master и пассивный репликационный Slave используется для обеспечения высокой доступности (High Availability) и отказоустойчивости. Пассивный сервер не принимает текущую нагрузку от пользователей, а лишь синхронизирует данные с основным.
- Быстрое аварийное переключение (Failover).
- Актуальность данных, пассивный сервер не тратит ресурсы на обработку сторонних запросов, репликация проходит быстро. Это минимизирует риск потери данных при аварии.
- Изоляция тяжелых операций. На пассивном сервере можно безопасно выполнять резервное копирование (бэкапы) или строить сложные аналитические отчеты. Это никак не повлияет на производительность активного Master, обслуживающего пользователей.
- Простота архитектуры. Приложению не нужно разделять запросы на чтение и запись по разным серверам. Все запросы идут в одну точку (на Master), что упрощает код и снижает вероятность ошибок синхронизации.
  
Master-сервер и несколько Slave-серверов
Эта схема ориентирована на горизонтальное масштабирование производительности системы в условиях, когда количество операций чтения значительно превышает количество операций записи (типично для веб-сайтов, соцсетей и контентных платформ).
- Масштабирование производительности чтения (Read Scalability). Нагрузка на чтение распределяется между несколькими Slave-серверами.
- Разгрузка Master-сервера. Главный сервер освобождается от выполнения запросов SELECT. Он тратит свои вычислительные мощности (CPU, RAM, дисковый ввод-вывод) исключительно на изменение данных (INSERT, UPDATE, DELETE).
- Повышенная надежность (Геораспределение). Несколько Slave-серверов можно разместить в разных дата-центрах или регионах.
- Гибкое распределение ролей. Разные Slave-серверы можно оптимизировать под конкретные задачи. Например: один Slave обслуживает API мобильного приложения, второй — аналитиков, третий используется только для бэкапов.
